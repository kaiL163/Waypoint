# Waypoint

Диспетчерская панель с FastAPI, OR-Tools, OSRM, PostgreSQL/PostGIS и React. Один `compose.yaml` поднимает интерфейс, API, базу и отдельные локальные графы OSRM для автомобиля, ходьбы и велосипеда.

## Запуск

1. Скопируйте `.env.example` в `.env` и замените `POSTGRES_PASSWORD`.
2. Запустите `docker compose up --build -d` из корня проекта.
3. Откройте `http://localhost:5173/`. Документация API: `http://localhost:5173/docs`.

Первый запуск загружает [OSM-экстракт Москвы BBBike](https://download.bbbike.org/osm/bbbike/Moscow/) (около 81 МБ) и последовательно готовит три графа OSRM. Это может занять несколько минут и потребовать дополнительного места/памяти. Параметр `OSM_PBF_URL` позволяет заменить экстракт; после смены уже подготовленных графов старый том OSRM нужно заменить отдельно. [Схема подготовки OSRM](https://github.com/Project-OSRM/osrm-backend#using-docker).

Docker Compose проверен синтаксически; полный запуск требует работающего Docker Desktop. Данные Postgres и OSRM лежат в именованных томах и сохраняются между перезапусками.

## Как работает планирование

- API принимает инженеров и заявки, сохраняет их в PostgreSQL. Координаты дополнительно хранятся в геометрических колонках PostGIS с пространственными индексами.
- OSRM Table даёт время и расстояние поездок для автомобильного, пешеходного и велосипедного профилей; OR-Tools подбирает назначение и порядок заявок с учётом смен, временных окон, длительности работ, навыка, транспорта и приоритета. Заявка может остаться неназначенной с пояснением. Пешеходный профиль использует размеченные в OSM проходы, дорожки и доступные пешеходам улицы; это не гарантия движения исключительно по тротуару. Велосипедный профиль использует разрешённые велодорожки и дороги, местами может предполагать ведение велосипеда пешком. [Профили OSRM](https://github.com/Project-OSRM/osrm-backend/blob/master/docs/profiles.md).
- Для общественного транспорта пока используется оценка по прямой с коэффициентом и средней скоростью. Это **не** маршрут с остановками, пересадками и расписанием. Для него нужен отдельный источник данных о рейсах и пересадках.
- Время в данных — локальное `HH:MM` одного рабочего дня; ночные смены и многодневное планирование пока не поддерживаются.
- Выбранные демо-данные и загруженные JSON/CSV сохраняются на сервере. Текущий план также сохраняется и восстанавливается после обновления страницы.

## API

Все пути начинаются с `/api`:

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка БД |
| `GET /engineers`, `GET /requests` | Текущие данные |
| `PUT /data/dataset` | Замена набора данных JSON |
| `POST /data/upload` | Загрузка файлов JSON/CSV (`files`) |
| `POST /planning/baseline` | Быстрый исходный план без сохранения |
| `POST /planning/optimize` | Оптимизация и сохранение плана |
| `POST /planning/replan` | Событие `urgent_request`, `cancel_request` или `engineer_unavailable` |
| `GET /planning/current` | Последний план |

Схемы запросов и ответов доступны в OpenAPI на `/docs` у FastAPI. CSV поддерживает UTF-8 и Windows-1251, разделители `;`/`,`; нужен `entity=engineer/request` или тип в имени файла. Для таблицы заявок Билайн поддержаны столбцы `Заявка`, `Тип заявки HD/BK`, `Адрес`, `Начало`, `Окончание` и обязательные `lat/lng` либо `Широта/Долгота`. Длительность заявки берётся из норматива **без фиксированных 20 минут дороги**, поскольку дорога рассчитывается отдельно.

## Локальная разработка

Сервис API использует переменные `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` (или единый `DATABASE_URL`), `OSRM_URL`, `OSRM_WALK_URL`, `OSRM_BIKE_URL`, `MAX_SOLVE_SECONDS`. Vite проксирует `/api` на `http://localhost:8000`. Для разработки можно поднять БД и все три сервера OSRM через Compose, затем запустить backend (`uvicorn app.main:app --reload` из `backend`) и frontend (`npm run dev` из `frontend`); при этом адреса DB/OSRM нужно выставить на доступные с хоста порты.

Сервис рассчитан на локальный стенд и **не имеет авторизации**. Перед публикацией в открытый интернет необходимы аутентификация, управление доступом, HTTPS и отдельные настройки секретов. Схема БД создаётся автоматически при запуске; для будущих изменений схемы потребуются миграции.
